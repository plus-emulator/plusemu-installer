Cloudflare has a free plan. Its proxy protects website traffic and provides HTTPS for visitors. The steps below also secure the connection to your server.
1

Add your domain to Cloudflare

  1. Go to dash.cloudflare.com and create a free account (or log in).
  2. Click Add a domain (sometimes called Add a site), type {{DOMAIN}} and click Continue.
  3. Choose the Free plan at the bottom and click Continue.
2

Point your domain to Cloudflare

Cloudflare now shows you two nameservers that look like anna.ns.cloudflare.com. Put them in at the company where you bought your domain:

  1. Log in where you bought {{DOMAIN}} (Namecheap, GoDaddy, Porkbun, …).
  2. Find your domain's Nameservers setting. On Namecheap: Domain List → Manage → Nameservers → Custom DNS.
  3. Remove the old nameservers, paste the two from Cloudflare and save.
  4. Back in Cloudflare, click Check nameservers.
This usually takes 5–30 minutes (rarely up to 24 hours). Cloudflare emails you when your domain is active. You can carry on with the next steps in the meantime.
3

Add your DNS records

In Cloudflare, open your domain and go to DNS → Records.

  1. Delete any existing records named {{DOMAIN}} (or @) and www of type A, AAAA or CNAME. Cloudflare sometimes copies old ones over.
  2. Click Add record and add the records below. Leave the Proxy status switch orange (Proxied).

Keep these records orange (Proxied). Visitors connect through Cloudflare; browsers do not directly trust the origin certificate installed below. The server accepts the hotel only from Cloudflare, so a grey (DNS only) record makes the hotel unreachable.
4

Install your Cloudflare origin certificate

The installer starts with a self-signed certificate. Replace it with a Cloudflare Origin CA certificate before enabling Full (strict).

The certificate must cover {{DOMAIN}}, www.{{DOMAIN}}, and your game connection at {{WS_HOST}}. Add each different hostname explicitly.

If your game connection uses a different domain Add its DNS record in that domain's Cloudflare zone. If Cloudflare cannot issue one certificate for all your hostnames, stop before running the single-certificate commands below. You need a separate certificate for each zone. On Linux, use separate certificate and key paths for the game's nginx server block instead of replacing the shared pair. On Windows, install the matching certificate on each hostname's HTTPS binding. Complete both certificates before enabling Full (strict) in both zones. Get help configuring those separate certificates before continuing.

5

Enable Full (strict)

  1. After installing and checking the certificate, open SSL/TLS → Overview in Cloudflare. Choose Full (strict) and save.
  2. Under SSL/TLS → Edge Certificates, check that the visitor certificate is active. Switch on Always Use HTTPS.
  3. Under Network, check that WebSockets is On.
Cloudflare manages the visitor certificate. The origin certificate you installed protects the connection from Cloudflare to your server. Keep the DNS records proxied.

If this Cloudflare zone also serves other websites, check their origin certificates before changing the zone-wide setting.

6

Open your hotel

  1. Visit https://{{DOMAIN}}. Check that the website loads over HTTPS. Also visit https://www.{{DOMAIN}} and confirm it redirects to your hotel. Use the troubleshooting section below if either fails.
  2. Log in with the admin username and password the installer showed you. They're also saved in {{CREDENTIALS_FILE}}.
  3. Change your password under Settings → Password.
  4. Click Enter hotel and check that the game connects. This also verifies the WebSocket hostname.

Manage your hotel (news, users, ranks, shop) at https://{{DOMAIN}}/housekeeping.

Connect to your database

Your database password was generated automatically. Read {{CREDENTIALS_FILE}} on your server as root or Administrator: use DB_PASSWORD on Linux or DbPassword on Windows.

Connect to MariaDB at 127.0.0.1:3306, database plus, username hotel. From your computer, use an SSH tunnel to the server with destination 127.0.0.1:3306. Keep the database port private.

Linux database root uses sudo mariadb with no generated root password. Windows saves its generated root password as DbRootPassword in the same file. Keep this file private; the website password stored there is the initial password, even after you change it.

Something isn't working?

Cloudflare error 521 or 522 Cloudflare can't reach your server. Check that the server is running and that the DNS records point to {{SERVER_IP}}. Some hosting companies also have a firewall in their control panel: allow ports 80 and 443 there.
Cloudflare error 526 Cloudflare cannot validate the origin certificate. Check its expiry and hostname coverage, then confirm nginx or IIS is serving the new certificate for the failing hostname. Check the www and {{WS_HOST}} bindings too. Correct the certificate or binding and keep Full (strict) enabled.
“Too many redirects” If SSL/TLS is set to Flexible, finish the origin-certificate steps and select Full (strict). If strict mode is already active, check your application redirect settings.
The client loads but disconnects, or stays on the loading screen Check that WebSockets is on in Cloudflare (Network), then restart the emulator: {{RESTART_COMMAND}}. Still stuck? Watch the log while you open the client: {{LOG_COMMAND}}.
Asking for help on DevBest Post what you did, what you see (a screenshot helps) and the last lines of the emulator log. Never post your passwords file or private key.
