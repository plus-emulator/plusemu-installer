A. Create a certificate request in IIS

  1. On your Windows server, open Internet Information Services (IIS) Manager as Administrator. Select the server name on the left.
  2. Open Server Certificates, then click Create Certificate Request.
  3. Enter {{DOMAIN}} as the Common name. Fill in the remaining organization and location fields.
  4. Choose Microsoft RSA SChannel Cryptographic Provider and a bit length of 2048 or higher.
  5. Save the request as plusemu-origin-request.txt in your administrator account's Documents folder. IIS keeps the private key on this server.
  6. Open the request in Notepad. Copy the whole request, including its BEGIN and END lines.

If you are resuming this step, reuse your pending request. Complete it on the same Windows server where you created it.

B. Sign the request in Cloudflare

  1. Open your domain in Cloudflare. Go to SSL/TLS → Origin Server → Create Certificate.
  2. Select Use my private key and CSR. Paste the request from Notepad. Do not paste or export the private key.
  3. Add all the hostnames listed above, even though the IIS request has only one common name. Choose a validity period and click Create.
  4. Select PKCS#7 for the certificate format. Save the returned certificate on the server as plusemu-origin.p7b in the same Documents folder. If copying its text into Notepad, use Save as type → All Files so it does not become a .txt file.

C. Complete the request and update your hotel

  1. In IIS Manager, return to the server's Server Certificates. Click Complete Certificate Request.
  2. Select plusemu-origin.p7b. Change the file picker to All Files if needed. Set a recognizable friendly name, such as PlusEMU Cloudflare Origin, and select the Personal certificate store.
  3. Open the completed certificate. Check the issuer, expiry date, and Details → Subject Alternative Name. Confirm it covers every hostname above and says that you have a corresponding private key.
  4. Expand Sites → Hotel and click Bindings. Note each existing HTTPS binding's certificate so you can restore it if needed.
  5. Edit the existing https binding for {{DOMAIN}}. Select the new certificate and save. Keep its hostname, port 443, and Require Server Name Indication setting unchanged.
  6. Repeat for the existing www.{{DOMAIN}} binding and the {{WS_HOST}} binding if that hostname is different. Update each binding once. Leave the HTTP bindings in place.

The new certificate takes effect on new connections. Continue below to enable Full (strict), then check the website and game connection.

The new certificate is missing or has no private key Return to the server where you created the request. Complete that exact request using its Cloudflare response. A certificate created from another request cannot use this server's pending key. Do not change the HTTPS bindings until the completed certificate has its private key.
Restore the previous IIS certificate Open Sites → Hotel → Bindings. Edit each changed HTTPS binding and select the certificate you noted earlier. Keep the hostname and SNI settings unchanged. An old self-signed certificate still cannot pass Full (strict); install a valid origin certificate to finish setup.
